# Architecture

## Monorepo

Nattyrex is a single repository with an independently deployable backend and frontend:

```
backend/   Django project `config` + apps `accounts` and `training`
frontend/  React/Vite SPA and PWA service worker
docs/      Operational and technical documentation
```

There are no nested git repositories. The frontend calls the versioned REST API under `/api/v1/`.

## Backend

### `accounts`

- Custom UUID `User` (email login, optional phone, role `TRAINER`/`CLIENT`).
- `TrainerProfile` and `ClientProfile` (clients always belong to exactly one trainer).
- `ClientInvitation` — hashed single-use token, expiry, revocation and usage timestamps.
- `Notification` — in-app events for clients and the trainer.
- Authentication: JWT access + rotating refresh tokens, refresh blacklist after rotation.
- Services: client creation, invitation creation/acceptance, activation.
- The single trainer is provisioned by `manage.py create_trainer`; no signup endpoint exists.

### `training`

| Model | Responsibility |
| --- | --- |
| `Exercise` | Reusable trainer-owned movement, defaults and coaching instructions |
| `ExerciseMedia` | Video/animation/image uploads or external URLs, one preferred demo |
| `WorkoutProgram` | Name, objective, date range, duration and draft/active status |
| `WorkoutWeek` | Week number and notes; weeks are generated from duration |
| `WorkoutDay` | Monday–Sunday slot, rest-day flag |
| `WorkoutSession` | A workout on a day; multiple sessions per day are supported |
| `WorkoutExercise` | Snapshot prescription (name, sets, reps, weight, notes, rest, tempo) |
| `ProgramAssignment` | Program ↔ client link, status, start date and program snapshot |
| `ExerciseCompletion` | Actual sets/reps/weight/notes per exercise |
| `WorkoutCompletion` | Finished session, notes and immutable session snapshot |
| `ClientProgress` | Dated weight, body fat, measurements and notes |
| `TrainerNote` | Private trainer notes about a client |

### Scheduling

Programs are organised Monday–Sunday. An assignment's start date is aligned to the Monday of its week, so a client assigned mid-week can train the current weekday immediately. Week 1 day 0 is that Monday; all client calendar, trainer dashboard and completion dates use the same helper.

`WorkoutExercise` copies exercise defaults at prescription time and stores snapshot text. If a library exercise is edited or deleted, historical prescriptions and completion snapshots remain meaningful.

### Completion rules

- Exercises can be logged individually with actual performance and notes.
- A workout can only be completed when every exercise is logged.
- Only `ACTIVE` assignments can finish workouts; exercises may be logged while paused.
- Once a workout is complete, exercise completions are locked until the session is undone at the database/service level (no API undo for finished sessions).
- Completion creates notifications for both client and trainer.

### Permissions

- `IsTrainer` / `IsClient` guard every endpoint by role.
- Trainer queries are scoped by `trainer=request.user`.
- Client queries are scoped through `request.user.client_profile`.
- Cross-trainer and unassigned resources return 404 to avoid leaking existence.
- Invitation preview/accept and login are the only public API actions (plus health/schema).

## Frontend

- React 18, TypeScript, Vite, Tailwind CSS, React Query, React Router.
- Route pages are lazy-loaded; the auth context bootstraps from `/auth/me/`.
- Tokens live in `localStorage` (`nattyrex.access`, `nattyrex.refresh`).
- The API client adds the bearer token, retries once after a successful refresh, and emits `nattyrex:session-expired` when refresh fails.
- Toast provider handles user-facing success/error messages.
- Design system in `src/components/ui` (buttons, cards, fields, modals, skeletons, empty states).
- Trainer shell and client shell share the responsive sidebar/bottom navigation.

### PWA and privacy

- `vite-plugin-pwa` generates the manifest and Workbox service worker.
- App shell/assets are precached for installation and offline fallback.
- `/api/` is explicitly `NetworkOnly`; private responses are never written to the cache.
- Uploaded media is not precached. The offline banner explains that live data requires connectivity.
- Icons are generated by a dependency-free script: `python frontend/scripts/generate_icons.py`.

## Data isolation and backups

- Production uses PostgreSQL via `DATABASE_URL`; local development defaults to SQLite.
- Exercise media uses local filesystem storage by default. An S3-compatible backend can be enabled with `STORAGE_BACKEND=s3` and the optional `django-storages` packages.
- Back up both the database and media volume. Database snapshots alone do not include trainer-uploaded videos and thumbnails.
